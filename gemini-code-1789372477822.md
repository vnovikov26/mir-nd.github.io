**Объект аудита:** `gemini-code-1789133318128_2.html` (Одностраничный сайт «Мир Недвижимости Дмитров»)
**Тестовые среды:** iOS (WebKit/Safari), Android (Blink/Chrome), macOS/Linux Desktop, iPadOS (планшеты)

## 2. Перечень выявленных замечаний

### Замечание 1. Отсутствие поддержки Safe Area (iOS Safari)
* **Локация:** Тег `<meta name="viewport">` и селектор `.mobile-bar`.
* **Суть проблемы:** Метатег остался в виде `<meta name="viewport" content="width=device-width, initial-scale=1" />`. Позиционирование `.mobile-bar` задано жестко (`bottom: 12px`). На безрамочных iPhone (начиная с iPhone X и до 15/16 Pro) кнопки «Позвонить» и «WhatsApp» перекрываются системной горизонтальной полосой смахивания (Home Indicator).
* **Требуемое исправление:**
  1. Добавить `viewport-fit=cover` в метатег `<head>`.
  2. Добавить `calc(12px + env(safe-area-inset-bottom, 0px))` для `.mobile-bar`.
  3. Добавить нижний отступ футера на мобильных разрешениях: `padding-bottom: calc(96px + env(safe-area-inset-bottom, 0px))`.

---

### Замечание 2. Эффект принудительного зума при вводе (Scale-Zoom на iOS)
* **Локация:** Поля `.slot-form input`, `.form input`, `.form select`, `.form textarea`.
* **Суть проблемы:** Если размер шрифта в активных элементах ввода составляет менее 16px, браузер Safari на iOS автоматически масштабирует экран при фокусе, что приводит к горизонтальному сдвигу макета и обрезке контента.
* **Требуемое исправление:**
  Явно объявить размер шрифта 16px для всех инпутов на мобильных разрешениях (`@media (max-width: 860px)`).

---

### Замечание 3. Пропуск адаптивной сетки для планшетов (861px — 1024px)
* **Локация:** Блок медиа-запросов `@media`.
* **Суть проблемы:** Брейкпоинт `@media (min-width: 600px) and (max-width: 860px)` перестраивает сетку только внутри мобильного диапазона. На экранах шириной 861px–1024px (iPad в портретной/альбомной ориентации) включаются полноразмерные десктопные правила:
  - Сетка Hero (`1.15fr .85fr`) сжимает правый блок бронирования.
  - Сетка команды `.crew-list` с 3 колонками сжимает карточки сотрудников до нечитаемого состояния.
* **Требуемое исправление:**
  Добавить медиа-запрос `@media (max-width: 1024px)` с переводом Hero в 1 колонку (`grid-template-columns: 1fr`) и карточек команды в адаптивный грид `repeat(auto-fit, minmax(220px, 1fr))`.

---

### Замечание 4. Мобильное меню не закрывается при навигации
* **Локация:** Скрипт переключения `#menuToggle` и `.nav-links`.
* **Суть проблемы:** При выборе якорной ссылки (например, переход к разделу `#irina` или `#how`) происходит скролл к нужному блоку, но класс `.open` не удаляется. Выпадающее меню продолжает перекрывать экран.
* **Требуемое исправление:**
  Добавить событие `click` на все ссылки списка навигации с удалением класса `.open` и сбросом атрибута `aria-expanded="false"`.

---

### Замечание 5. Локальное хранение остатка слотов (`localStorage`)
* **Локация:** Константы `SLOT_CAP = 3`, `SLOT_STORE` и методы `getCounts()`, `renderSlots()`.
* **Суть проблемы:** Счётчик забронированных мест сохраняется только в браузере текущего пользователя. Бронирование одним пользователем не уменьшает количество доступных мест для остальных посетителей сайта.
* **Требуемое исправление:**
  Для продакшена необходимо подключить эндпоинт базы данных (Supabase, Firebase, Google Apps Script или собственный REST API) для единого подсчёта оставшихся записей на дату.
